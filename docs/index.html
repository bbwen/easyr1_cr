Overview

Standard LLMs often exhibit systematic overconfidence. ReCon addresses this by requiring models to explicitly reflect on uncertainty before reporting a calibrated confidence score. Built on the EasyR1 RL framework, this repository implements VeriConf-GRPO — GRPO training with rewards for both correctness and confidence calibration.

◆

Reflective Confidence (ReCon)

Structured output format combining reasoning, answer, uncertainty analysis, and a numeric confidence score in [0, 1].

★

VeriConf-GRPO

GRPO variant that jointly optimizes task accuracy and calibration via format, accuracy, and Brier score rewards.

⚙

Unified Evaluation

End-to-end evaluation on HotpotQA (text) and MathVista (vision-language) with multiple confidence baselines.

📊

Calibration Metrics

Accuracy, AUROC, Brier Score, and Expected Calibration Error (ECE) for rigorous confidence assessment.

Method

ReCon forces models through an explicit reflection step before committing to a confidence value, reducing overconfidence and improving reliability in downstream decision-making.

Step 1

Reason

Model works through the problem inside structured thinking tags.

Step 2

Answer

Final response is produced in a dedicated answer block.

Step 3

Reflect

Model analyzes uncertainties, ambiguities, and potential failure modes.

Step 4

Confide

A calibrated score in [0, 1] is reported alongside the answer.

Required Output Format
<redacted_thinking>
  reasoning process
</redacted_thinking>

<answer>
  final answer
</answer>

<analysis>
  reflection on uncertainty and limitations
</analysis>

<confidence>
  confidence score in [0, 1]
</confidence>
VeriConf-GRPO Reward Components

Format reward — enforces the structured ReCon output format and valid confidence range.

Accuracy reward — binary reward for correct final answers against ground truth.

Brier reward — calibration signal: 1 − (correctness − confidence)²

Compare against vanilla GRPO (config_ori.yaml) and VeriConf-GRPO (config_conf.yaml) training configs.

Quick Start

Get started with Docker, train with GRPO, merge checkpoints, and run evaluation.

1

Environment Setup

Recommended: use the official Docker image with GPU support.

docker run --gpus all -it --ipc=host \
  -v $(pwd):/workspace/easyr1_cr \
  hiyouga/verl:ngc-th2.8.0-cu12.9-vllm0.11.0 bash
2

Train with VeriConf-GRPO

Run training scripts for HotpotQA (text) or MathVista (vision-language).

# HotpotQA — VeriConf-GRPO
bash examples/qwen3_4b_hotpot_grpo_conf.sh

# MathVista — VeriConf-GRPO
bash examples/qwen2_5_vl_3b_mathvista_grpo_conf.sh
3

Merge Checkpoints

Merge FSDP shards before evaluation.

python scripts/model_merger.py \
  --local_dir checkpoints/easy_r1/<experiment>/global_step_x/actor
4

Evaluate

Run evaluation with a JSON config specifying datasets and model checkpoints.

# Text tasks
python evaluation.py --config eval_configs/Hotpot-models/hotpot-vanilla-eval-em.json

# Vision-language tasks
python evaluation_vl.py --config eval_configs/Hotpot-models/mathvista_eval-em.json
